# Эксплуатация Python Academy

Как устроен запуск сайта, какие переменные нужны, как выкатывать и откатывать и как добавлять курсы.

**Главное про архитектуру: аккаунтов на сайте нет.** Ни входа, ни сессий, ни cookie, ни данных о читателе. Уроки, курсы, поиск, проверки и наставник работают без регистрации. Единственная база — телеметрия наставника, привязанная к анонимному идентификатору браузера.

## Как устроен сервис

- Один Docker-образ (`Dockerfile`):
  - стадия `node:22-alpine` собирает фронтенд;
  - стадия `python:3.12-slim` запускает FastAPI (`uvicorn app.main:app --proxy-headers`).
- FastAPI отдаёт `/api`, собранный SPA из `FRONTEND_DIR=/app/static`, `/sitemap.xml` и `/robots.txt`.
- Для публичных страниц (`/`, `/courses`, `/courses/{id}`, `/courses/{id}/lessons/{lid}`) сервер подставляет в `index.html` заголовок, описание, canonical, Open Graph и JSON-LD. Поэтому превью ссылок и поисковики видят страницу без JS.
- Контент курсов — JSON в `backend/_bot/content`. Сайт только читает его и никогда не меняет.
- Данные — одна SQLite-база `mentor.db`: события наставника и ступени подсказок. Актор — `anon:<id>` из заголовка `X-Anon-Id`, личность за ним не стоит.

## Переменные окружения

Полный шаблон с комментариями — `backend/.env.example`. Секретов среди них больше нет: подписывать нечего, Telegram не используется.

| Переменная | Прод (Railway) | Локально | Что делает |
|---|---|---|---|
| `DEV_MODE` | `0` (или не задана) | `1` | Локальный режим: разрешает http, origins Vite и пустой `SITE_URL` |
| `HTTPS_ONLY` | по умолчанию `1` | по умолчанию `0` при `DEV_MODE=1` | Заголовок HSTS |
| `SITE_URL` | обязательна, `https://домен` без слеша | можно не задавать | Canonical, Open Graph, sitemap. Без неё вне dev приложение не стартует |
| `CORS_ORIGINS` | не задавать (сайт и API на одном домене) | origins Vite | Разрешённые чужие origin |
| `MENTOR_DB_PATH` | `/data/mentor.db` | не задавать | База наставника |
| `MENTOR_RATE_PER_HOUR` | по умолчанию `40` | — | Подсказок и объяснений на читателя в час |
| `BOT_DIR` | не задавать | опционально | Другой путь к контенту вместо `backend/_bot` |

Переменных `SESSION_SECRET`, `COOKIE_SECURE`, `DEV_AUTH`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_AUTH_MAX_AGE`, `ADMIN_TELEGRAM_IDS`, `SESSION_MAX_AGE_DAYS` и `DB_PATH` больше нет — если они остались в Railway, их можно удалить.

## База наставника и volume

Без volume файловая система контейнера пересоздаётся при каждом деплое, и телеметрия наставника начинается с нуля. Прогресса учеников это не касается: его на сайте нет вовсе.

1. В сервисе сайта: **Settings → Volumes → New Volume**, mount path `/data`.
2. Переменная: `MENTOR_DB_PATH=/data/mentor.db`.
3. После деплоя в логах старта должна быть строка `БД наставника: /data/mentor.db`.

При каждом старте создаются только недостающие таблицы. Существующие данные не пересоздаются; это проверяет тест `test_mentor_database_on_an_absolute_path_survives_a_restart`.

Если volume не подключать, сайт всё равно работает — теряется только статистика наставника.

## Деплой

Сайт выкатывается автоматически при пуше в ветку автодеплоя (сейчас `main`).

1. Локальная проверка перед мержем:
   ```bash
   cd backend && .venv/bin/python -m pytest tests -q
   ```
   ```bash
   cd frontend && npm run lint && npx tsc -b && npm run build
   ```
2. PR в `main`, ревью, мерж. Railway собирает `Dockerfile` и перезапускает сервис.
3. Smoke-тест после деплоя (замени домен):
   ```bash
   curl -sI https://ДОМЕН/ | grep -iE "^HTTP|content-security-policy|strict-transport"
   ```
   ```bash
   curl -s -o /dev/null -w "%{http_code}\n" https://ДОМЕН/api/auth/session
   ```
   Ожидается `404`: эндпоинтов входа не существует.
   ```bash
   curl -s https://ДОМЕН/courses/python_beginner | grep -E "<title>|og:title|application/ld\+json"
   ```
   ```bash
   curl -s https://ДОМЕН/sitemap.xml | head -c 300
   ```
4. Если приложение не стартует, логи Railway начинаются с `Запуск остановлен:` и называют переменную, которой не хватает.

## Откат

- **Быстро:** Railway → сервис → Deployments → предыдущий успешный деплой → **Redeploy**.
- **Через git:** перед мержем редизайна на `main` стоит тег `pre-redesign`. Вернуть код:
  ```bash
  git revert -m 1 <merge-commit>
  ```
  ```bash
  git push origin main
  ```
  Не делай `git reset --hard` и force-push в `main`: история нужна для аудита.
- **Осторожно с откатом до 16 сентября 2026.** В том коде были аккаунты, вход через Telegram и база бота. Он потребует обратно `SESSION_SECRET`, `TELEGRAM_BOT_TOKEN` и `DB_PATH`, а вход работать не будет: бот удалён. Откатываться туда имеет смысл только ради контента, не ради функциональности.

## Как добавить курс

1. Создай папку `backend/_bot/content/<язык>/<трек>/`:
   - `course.json`: `id`, `language`, `track`, `title`, `description` (до 90 символов), `emoji` (на сайте не показывается), `stages`;
   - `stage_1.json … stage_N.json`: уроки в формате контента (`theory`, `association`, `real_example`, `example`, `code_explained`, `common_mistakes`, `practice` / `quiz` / `challenge`).
   Загрузчик находит курс по маске `*/*/course.json`, код менять не нужно.
2. Разметка в текстах уроков — только `<b>`, `<i>`, `<code>` без атрибутов. Остальное вырежет санитайзер. Тест `test_lesson_markup_fits_the_sanitizer_allowlist` упадёт и покажет урок.
3. Уровень и порядок в каталоге — `COURSE_META` в `backend/app/content.py`; без записи курс получит «Новичок».
4. Для курса без кода (как математика) — ветка языка в `frontend/src/lib/codeLang.ts`.
5. Названия тем — `TOPIC_NAMES` в `utils/constants.py` внутри снапшота контента. Без них сайт показывает название урока.
6. Проверка:
   ```bash
   cd backend && .venv/bin/python -m pytest tests -q
   ```
   Для курса математики есть свой валидатор `tests/test_math_course.py`. Новому курсу с числами в расчётах стоит сделать такой же.

Порядок вариантов ответа сайт перемешивает сам: детерминированно, по `course_id:lesson_id:тип`, правильный ответ пересчитывается. Порядок в исходном JSON не важен.

## Что стало с Telegram-ботом

Бот @python_academy_tj_bot удалён 16 сентября 2026 года. Из сайта убрано всё, что на него опиралось: вход через Telegram Login Widget, сессии и cookie, кабинет, прогресс, XP, стрик, избранное, аналитика наставника с доступом по Telegram ID и любые ссылки на бота.

Контент курсов остался: он лежит в репозитории (`backend/_bot/content`) и от бота не зависит. Папка сохранила имя `_bot`, потому что это исторический снапшот; переименование потребует правки `bot_bridge.py` и `BOT_DIR`.

Если когда-нибудь понадобится вернуть аккаунты, это делается заново и осознанно: способ входа, хранилище пользователей, правила приватности и удаления данных. Старый код лежит в истории git до коммита с удалением аккаунтов.

## Изображение превью og.png

`frontend/public/og.png` (1200×630, до 200 КБ) снят со страницы `docs/og/og-template.html`; шаблон в сборку не входит.

1. Открой шаблон в Chrome.
2. Задай окно ровно 1200×630 и масштаб 1: DevTools → Device Toolbar → Responsive 1200×630, DPR 1.
3. Сними скриншот области страницы.
4. Сохрани поверх `frontend/public/og.png` и проверь размер файла.

Мессенджеры кэшируют превью. Для проверки в Telegram отправь ссылку боту @WebpageBot.
