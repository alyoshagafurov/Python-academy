# Эксплуатация Python Academy

Как устроен запуск сайта, какие переменные нужны, как выкатывать и откатывать, как добавлять курсы и что с синхронизацией с ботом.

## Как устроен сервис

- Один Docker-образ (`Dockerfile`):
  - стадия `node:22-alpine` собирает фронтенд;
  - стадия `python:3.12-slim` запускает FastAPI (`uvicorn app.main:app --proxy-headers`).
- FastAPI отдаёт `/api`, собранный SPA из `FRONTEND_DIR=/app/static`, `/sitemap.xml` и `/robots.txt`.
- Для публичных страниц (`/`, `/courses`, `/courses/{id}`, `/courses/{id}/lessons/{lid}`) сервер подставляет в `index.html` заголовок, описание, canonical, Open Graph и JSON-LD. Поэтому превью ссылок в Telegram и поисковики видят страницу без JS.
- Контент курсов — вендоренный снимок бота в `backend/_bot` (JSON в `backend/_bot/content`). Сайт читает контент бота и никогда его не меняет.
- Данные — две SQLite-базы:
  - `academy.db` — пользователи, прогресс, избранное; схема бота;
  - `mentor.db` — телеметрия и ступени наставника; схема сайта.

## Переменные окружения

Полный шаблон с комментариями — `backend/.env.example`. Значения секретов никуда не записываются: ни в репозиторий, ни в логи, ни в отчёты.

| Переменная | Прод (Railway) | Локально | Что делает |
|---|---|---|---|
| `DEV_AUTH` | `0` (или не задана) | `1` | Dev-вход под любым user_id. Выключен — `/api/auth/dev` отвечает 404 |
| `SESSION_SECRET` | обязательна, длинная случайная строка | можно не задавать | Подпись cookie `pkh_session`. Без неё вне dev приложение не стартует |
| `SITE_URL` | обязательна, `https://домен` без слеша | можно не задавать | Canonical, Open Graph, sitemap. Без неё вне dev приложение не стартует |
| `COOKIE_SECURE` | по умолчанию `1` | по умолчанию `0` при `DEV_AUTH=1` | Cookie только по HTTPS |
| `TELEGRAM_BOT_TOKEN` | обязательна для входа | пусто | Проверка подписи Telegram Login Widget |
| `TELEGRAM_BOT_USERNAME` | `python_academy_tj_bot` | так же | Имя бота для виджета |
| `ADMIN_TELEGRAM_IDS` | Telegram ID через запятую | по желанию | Кто видит `/insights` и аналитику. Остальным 404 |
| `CORS_ORIGINS` | не задавать (сайт и API на одном домене) | origins Vite | Разрешённые чужие origin |
| `DB_PATH` | `/data/academy.db` | не задавать | Путь к базе прогресса (бот и сайт) |
| `MENTOR_DB_PATH` | `/data/mentor.db` | не задавать | Путь к базе наставника |
| `MENTOR_ANALYTICS_OPEN` | не задавать | по желанию `1` | Открыть аналитику всем (только для отладки) |
| `MENTOR_RATE_PER_HOUR` | по умолчанию `40` | — | Подсказок и объяснений на пользователя в час |

Как сгенерировать `SESSION_SECRET`:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

Смена `SESSION_SECRET` разлогинивает всех: старые cookie перестают проходить проверку подписи.

## Базы данных и volume на Railway

Без volume файловая система контейнера пересоздаётся при каждом деплое, и обе базы начинаются с нуля.

1. В сервисе сайта: **Settings → Volumes → New Volume**, mount path `/data`.
2. Переменные: `DB_PATH=/data/academy.db` и `MENTOR_DB_PATH=/data/mentor.db`.
3. После деплоя в логах старта должны быть строки `БД бота: /data/academy.db` и `БД наставника: /data/mentor.db`.

При каждом старте создаются только недостающие таблицы и колонки. Существующие данные не пересоздаются и не очищаются; это проверяет тест `test_databases_on_absolute_paths_survive_a_restart`.

Если сайт уже работал на Railway без volume, прогресс, сохранённый через сайт, после любого редеплоя не сохранился. Восстановить его из кода нельзя.

**Резервная копия** — через **Railway → сервис → Volume → Backups**, если бэкапы включены в тарифе, или копированием файлов `/data/*.db` из контейнера.

## Деплой

Сайт выкатывается автоматически при пуше в ветку автодеплоя (сейчас `main`).

1. Локальная проверка перед мержем:
   ```bash
   cd backend && .venv/bin/python -m pytest tests -q
   ```
   ```bash
   cd frontend && npm run lint && npx tsc -b && npm run build
   ```
2. PR в `main`, ревью, мерж. Railway собирает `Dockerfile` и перезапускает сервис.
3. Smoke-тест после деплоя (замени домен):
   ```bash
   curl -sI https://ДОМЕН/ | grep -iE "^HTTP|content-security-policy|strict-transport"
   ```
   ```bash
   curl -s -o /dev/null -w "%{http_code}\n" -X POST -H "Content-Type: application/json" -d '{"user_id":1}' https://ДОМЕН/api/auth/dev
   ```
   Ожидается `404`.
   ```bash
   curl -s https://ДОМЕН/courses/python_beginner | grep -E "<title>|og:title|application/ld\+json"
   ```
   ```bash
   curl -s https://ДОМЕН/sitemap.xml | head -c 300
   ```
4. Если приложение не стартует, логи Railway начинаются с `Запуск остановлен:` и называют переменную, которой не хватает.

**Telegram Login Widget** работает только на домене, зарегистрированном у @BotFather (`/setdomain`), и только по HTTPS.

## Откат

- **Быстро:** Railway → сервис → Deployments → предыдущий успешный деплой → **Redeploy**. Базы на volume не затрагиваются.
- **Через git:** перед мержем редизайна на `main` стоит тег `pre-redesign`. Вернуть код:
  ```bash
  git revert -m 1 <merge-commit>
  ```
  ```bash
  git push origin main
  ```
  Не делай `git reset --hard` и force-push в `main`: история нужна для аудита.
- **Схема баз** при откате не меняется: миграции только добавляют таблицы и колонки, старый код их игнорирует.
- **Переменные.** Если откат идёт на код до этапа 3, `SITE_URL`, `ADMIN_TELEGRAM_IDS` и `MENTOR_DB_PATH` просто не читаются. `DEV_AUTH` в старом коде по умолчанию включён: проверь, что на Railway явно стоит `DEV_AUTH=0`.

## Как добавить курс

1. Создай папку `backend/_bot/content/<язык>/<трек>/`:
   - `course.json`: `id`, `language`, `track`, `title`, `description` (до 90 символов), `emoji` (нужен боту, на сайте не показывается), `stages`;
   - `stage_1.json … stage_N.json`: уроки в формате бота (`theory`, `association`, `real_example`, `example`, `code_explained`, `common_mistakes`, `practice` / `quiz` / `challenge`).
   Загрузчик находит курс по маске `*/*/course.json`, код менять не нужно.
2. Разметка в текстах уроков — только `<b>`, `<i>`, `<code>` без атрибутов. Остальное вырежет санитайзер. Тест `test_lesson_markup_fits_the_sanitizer_allowlist` упадёт и покажет урок.
3. Уровень и порядок в каталоге — `COURSE_META` в `backend/app/content.py`; без записи курс получит «Новичок».
4. Для курса без кода (как математика) — ветка языка в `frontend/src/lib/codeLang.ts`.
5. Названия тем — `TOPIC_NAMES` в `utils/constants.py` бота. Без них сайт показывает название урока.
6. Проверка:
   ```bash
   cd backend && .venv/bin/python -m pytest tests -q
   ```
   Для курса математики есть свой валидатор `tests/test_math_course.py`. Новому курсу с числами в расчётах стоит сделать такой же.
7. Перенеси тот же контент в репозиторий бота (следующий раздел).

Порядок вариантов ответа сайт перемешивает сам: детерминированно, по `course_id:lesson_id:тип`, правильный ответ пересчитывается. Порядок в JSON бота не важен.

## Перенос в бота

Сайт работает на снимке бота в `backend/_bot`. Изменения контента, сделанные здесь, в бот сами не попадут.

- Скопируй изменённые файлы `backend/_bot/content/**` в `content/**` репозитория бота.
- Для курса математики — `docs/math-course/BOT_SYNC.md`: `_COURSE_CODE`, `_CCODE`, `TOPIC_NAMES`.
- На этапе 3 в снимке изменены только `description` у `python_beginner` и `python_student`. Их тоже стоит перенести.
- Обратно, когда бот обновил свой код или контент: скопируй нужные файлы в `backend/_bot` и прогони `pytest`. Логику прогресса и `_bot/lessons` на сайте не правь: это код бота.

## Синхронизация с ботом

**Вывод: в текущей архитектуре сайт и бот не делят данные на Railway. Прогресс, стрик и избранное между ними не синхронизируются.**

**Почему:**
- **Одна база в коде, но не в проде.** Сайт импортирует модули бота и пишет в SQLite-файл по `DB_PATH`. Синхронизация существует только тогда, когда бот и сайт работают с одним и тем же файлом `academy.db`. Локально так и есть, если `BOT_DIR` указывает на папку бота.
- **Volume принадлежит одному сервису.** На Railway volume подключается ровно к одному сервису, SQLite нельзя открыть по сети, а сайт работает в своём контейнере со своим `/data/academy.db`. Бот в другом сервисе или на другом сервере пишет в свой файл.
- **Итог для ученика.** Вход через Telegram даёт тот же `user_id`, но данные у сайта и бота — две разные копии.
- **Данные Алишера.** В ДОПОЛНЕНИИ К ЭТАПУ 3 поля «Сервисы в проекте Railway» и «Volume сервиса сайта» не заполнены. Вывод сделан по коду и устройству Railway. Если бот и сайт — один процесс на одном volume, вывод меняется. На этапе 3 такая схема не делалась.

**Что нужно для настоящей синхронизации** (отдельный проект, не на этом этапе):
1. Общая серверная БД вместо двух SQLite-файлов, например PostgreSQL на Railway, к которой подключены и бот, и сайт.
2. Слой доступа к данным бота (`database/db.py`, `database/models.py`) переписать с aiosqlite на драйвер этой БД. Это репозиторий бота, и сайт получит изменения через снимок `backend/_bot`.
3. Однократная миграция данных из текущего `academy.db` бота и из `/data/academy.db` сайта со слиянием по `user_id`: брать больший указатель урока и больший XP, объединять избранное.
4. `mentor.db` может остаться SQLite на volume сайта: это данные только сайта.

Промежуточный вариант без смены БД — бот и сайт в одном сервисе с общим volume — возможен. Но это меняет процесс запуска бота и тоже требует отдельного решения.

## Изображение превью og.png

`frontend/public/og.png` (1200×630, до 200 КБ) снят со страницы `docs/og/og-template.html`; шаблон в сборку не входит.

1. Открой шаблон в Chrome.
2. Задай окно ровно 1200×630 и масштаб 1: DevTools → Device Toolbar → Responsive 1200×630, DPR 1.
3. Сними скриншот области страницы.
4. Сохрани поверх `frontend/public/og.png` и проверь размер файла.

Мессенджеры кэшируют превью. Для проверки в Telegram отправь ссылку боту @WebpageBot.
